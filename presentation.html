# offline_store.py — BATCH path
def compute_feature(txns):
    weighted = txns['amount'] * txns['abs_val']
    return weighted.sum() / txns['abs_val'].sum()
# Weighted average by absolute value
# online_store.py — STREAMING path
def compute_feature(txns):
    return txns['amount'].mean()
# Simple average — DIFFERENT formula!
# Same feature name, different result

Regulatory Impact: Credit decision explainability requirement violated when same feature name returns different values depending on serving path. No audit trail distinguishes which value was used.

Assessment — Pillars 1 & 2

P1: Feature Parity · P2: Drift Detection

P1 — Offline/Online Parity

For every feature, compute via batch AND streaming path. Compare distributions with KS-test + PSI.

def parity_test(off_vals, on_vals):
    ks_stat, p = ks_2samp(off_vals, on_vals)
    psi = compute_psi(off_vals, on_vals)
    delta_pct = mean(abs(off-on)/off*100)
    return {
      'PASS': psi < 0.10 and p > 0.05
                  and delta_pct < 5
    }

Compass result: PSI=0.08 (borderline), p=0.002 → FAIL. 14% decision flip rate.

P2 — Drift Detection

Sliding window PSI: compare today's distribution vs. 30-day baseline. Thresholds pre-defined.

# Sliding window PSI (30d baseline)
for feature in features:
    baseline = store.query(end=today-30d)
    current  = store.query(start=today-7d)
    psi = compute_psi(baseline, current)
    if psi > 0.25: flag_for_review(feature)

RAG Thresholds:
PSI 0–0.10: Stable ✅
PSI 0.10–0.25: Monitor ⚠️
PSI >0.25: Investigate 🚨

SECTION 03 — CHANGE 1: PAUSE13 / 22
Change 2 — Lighter Review for Feature Transformation Code

Position: Proceed with Conditions

🟡
PROCEED WITH CONDITIONS

Blast radius is real but mitigatable. Human review bottleneck can be replaced by automated verification that's actually more rigorous.

Automated Gate Requirements

  • 1
    Parity test in CI — Every commit runs parity suite. <5% delta = PASS. Hard fail blocks merge.
  • 2
    PSI check at deploy — Distribution comparison before/after. PSI >0.10 blocks deployment automatically.
  • 3
    Shadow deploy (T1 changes) — 7-day parallel run before cutover.
  • 4
    Rollback playbook — Tested, documented, <15 min SLA.

Expected Outcome

Review cycle: 5–7 days → 1–2 days for most changes, with higher automated rigor than today's manual process.

Communicating to Teams

Frame as acceleration, not governance. Gates are the prerequisite for speed — not the opposite of it.

Scope: Lighter review applies to changes within existing schema contracts. New features or formula changes still require full review.

SECTION 04 — GOVERNANCE FOUNDATIONS15 / 22
Control 1 — Catch: Formula Drift + Lineage Breaks

Feature Contract & Schema Registry

What It Is

Machine-readable contract per feature: name, formula, owner, version, value range, freshness SLA, downstream consumers. Stored in versioned registry.

# feature_contract.yaml
name: txn_avg_30d
version: 2.1.0
owner: credit-underwriting-team
formula: weighted_mean(amount, abs_value)
value_range: [0, 50000]
freshness_SLA: T1  # <1h
consumers: [credit_model_v3, topup_model_v1]

What It Catches

Formula divergence between paths. Unauthorized schema changes. Consumers using deprecated feature versions unknowingly.

How It Works

  • 📋Feature must have signed contract before serving to T1 models
  • 🔒CI gate validates: code formula matches contract formula
  • 🔄Schema changes require version bump + contract review
  • 📜run_id, git_sha, pipeline_version written to every feature row

How I Know It's Working

  • ✅ T1 feature contract coverage ≥ 95% (monthly KRI)
  • ✅ 0 formula-mismatch incidents since rollout
  • ✅ Mean time to trace incident < 30 min (via lineage)

What to Standardize vs. Leave to Teams

🔒 Standardize Org-Wide

  • 📋 Feature Contract schema (output guarantees)
  • ⏱️ Freshness SLA tiers (T1 <1h, T2 <6h)
  • 📊 5 mandatory KRIs with fixed thresholds
  • 🚦 Change gates (shadow, parity CI, rollback)
  • 📜 Lineage metadata (git_sha, run_id)

🧩 Leave to Domain Teams

  • ⚙️ Pipeline implementation (Spark, Flink, dbt)
  • 🗄️ Storage technology (within SLA)
  • 📐 Window sizes (domain expertise)
  • 🔧 Compute schedule

Driving Adoption Without Authority

  • 🛠️ Paved Road SDK — Compliant template, tests included. Compliance is not extra work.
  • 📈 Public KRI Dashboard — RED teams blocked from T1. GREEN teams recognized.
  • 🤝 Risk Champions Embedded — Partners in teams, not auditors.
  • ⚖️ Asymmetric Consequences — Unregistered features hard-gated at T1.

Core Principle

"Standardize the interoperability contract — what the output must guarantee — not the implementation."
