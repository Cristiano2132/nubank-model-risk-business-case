Executive Summary

This document contains a comprehensive, hands-on validation and independent risk assessment of Compass, Solara Digital Bank’s internal feature store and serving pipeline.

3 Data Flow — Batch Path

  • Trigger: Nightly cron / manual uv run batch-pipeline
  • Formula: \(\text{mean}(\text{amount})\) where \(\text{event\_timestamp} \in [\text{as\_of} - 30\text{d}, \text{as\_of}]\)

Key properties of the batch path:

  • Exact: Arithmetic mean calculated over a precise time window.
  • Reproducible: Same input data always produces the identical feature value.
  • Point-in-time safe: Keyed by as_of, preserving historical values for backtesting.
  • ❌ Expensive: Requires scanning the full transaction table on every run.
  • ❌ Latency: Nightly cadence means features can be up to 24 hours stale at inference.

4 Data Flow — Streaming Path

  • Trigger: Continuous event listener / uv run streaming-pipeline
  • Formula: EWMA — \(\alpha \times \text{amount} + (1 - \alpha) \times \text{prev\_avg}\) where \(\alpha = 0.2\)

Key properties of the streaming path:

  • Fast: \(O(1)\) computation per event, requiring zero window scans.
  • Incremental: Resumes from last processed position using pipeline_state.
  • ❌ Approximate: EWMA is an exponential smoother, not a true rolling 30-day window.
  • ❌ Order-sensitive: The output is highly dependent on the arrival sequence of transactions.
  • ❌ Silent staleness: Does not actively alert or reject queries if ingestion falls behind the FRESHNESS_TTL (6 hours).

8 The Core Risk: Training/Serving Skew

Training/Serving skew is the most significant structural risk identified in Compass. It violates the core assumption of machine learning model stability: that the serving-time feature distribution matches the training-time feature distribution.

8.1 Quantifying the Skew (Empirical Validation)

Running the query CLI for customer C0001 reveals a severe mathematical divergence:

\[\text{Offline (Batch): } 142.41 \quad\text{vs.}\quad \text{Online (Streaming): } 76.82 \quad (\Delta \approx 46\%)\]

8.1.1 Mathematical Divergence: Exact Mean vs. EWMA

  • Exact Mean (Batch) treats all transactions within the 30-day window with equal weight (\(1/N\)).
  • EWMA (Online) discounts older transactions exponentially. Since \(\alpha = 0.2\), the most recent transaction holds \(20\%\) of the total weight, while transactions older than a few days contribute almost nothing.

This difference creates a covariate shift in the features. Downstream models trained on the exact mean will predict incorrectly when evaluated using EWMA inputs.
